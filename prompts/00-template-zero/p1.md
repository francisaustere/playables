Build "Template Zero": the reusable foundation of a family of YouTube Playables game templates. No gameplay yet. Visuals are flat geometric primitives only. Code quality matters more than looks: other people will remix this with prompts.

HARD CONSTRAINTS
- No network calls, CDN, web fonts, images or audio files. Only external script: <script src="https://www.youtube.com/game_api/v1"></script>, first script in index.html before any game code.
- No localStorage, cookies or IndexedDB. Do not lock orientation. Relative paths only. Zero console errors.

1. GAME SPEC
All tunable values (numbers, colors, strings, sounds, timings) live in game_spec.json, read once at boot and deep-merged over defaults; invalid numbers are clamped, never crash. If fetching a local file is not possible, embed it as a single const GAME_SPEC in its own module. Units: stage units for distances, seconds for time, degrees, 0..1 ratios, colors as palette token names. Create game_spec.json with these sections (more come in the next prompts):
{{GAME_SPEC:meta,display,text,rules,limits,debug}}

2. PLATFORM (SDK wrapper)
Module "platform" wraps window.ytgame. hasSdk = typeof ytgame !== 'undefined' && ytgame.IN_PLAYABLES_ENV. Without SDK every call is a stub so the game always runs in a normal browser. Every promise gets a .catch().
- game.firstFrameReady() once, right after the first frame is drawn.
- game.gameReady() once, on the first Title frame that accepts input.
- engagement.sendScore({value}) with an integer.
- game.loadData()/saveData(string), system.getLanguage(), system.isAudioEnabled(), system.onAudioEnabledChange(cb), system.onPause(cb), system.onResume(cb).
- window error and unhandledrejection -> health.logError(), keep running.
Never use the Page Visibility API for pausing.

3. VIEWPORT
Canvas fills the window (100vw x 100dvh, no scroll). Logical stage = display.stage (720x1280). fit "contain": uniform scale, centered, extra space filled with palette bg. fit "expand": keep the stage short side, show more world on the long side. Canvas resolution = CSS size x min(devicePixelRatio, display.maxDpr). Recompute on resize/orientationchange (debounced 100 ms) and redraw at once, even when paused. Provide screenToStage(x, y) and the visible screen rect in stage units so HUD can anchor to real screen edges plus display.safeMargin and env(safe-area-inset-*). Must work from 9:32 to 32:9.

4. LOOP
One requestAnimationFrame loop, fixed simulation step 1/60 s with accumulator, max 4 steps per frame, frame delta clamped to 0.1 s, multiplied by debug.timeScale. All gameplay timers use game time, never setTimeout/setInterval. No allocations inside the loop (no new objects, arrays, closures or array callbacks per frame); provide a generic object Pool (acquire/release, fixed size from limits, skip spawn when empty) and swap-and-pop removal.

5. STATE MACHINE
States BOOT, TITLE, PLAY, PAUSED, RESULT, each with enter/update/render/exit.
BOOT: bg + small loading dots; call firstFrameReady after first draw; load save (1.5 s timeout) and language; then TITLE.
TITLE: game title, best score, controls hint, text.tapToStart. Call gameReady on first interactive frame. Confirm -> PLAY.
PLAY: fresh run reset from the spec every time. Pause button (top-right) or Escape/P -> PAUSED. SDK onPause -> PAUSED from any state of play.
PAUSED: game frozen and dimmed, "Paused", buttons Resume and Quit (-> TITLE). Never auto-resume, even on SDK onResume.
RESULT: win/lose title, score, best, "New best!" if beaten, buttons Play again and Menu. Ignore input for rules.resultInputDelay. On enter: sendScore + save.
Placeholder for now: PLAY shows "Gameplay goes here" and Space/tap ends the run with score 0.

6. MODULES
Separate modules: spec, platform, viewport, loop, pool, game (states), ui, draw. Each starts with a 2-4 line comment saying what it does and which spec sections it reads. Plain English names matching spec keys.

Show the structure and make sure it runs without errors.
