Keep everything from the previous step. Now add the style kit, input, audio and save. Add these sections to game_spec.json and read every value from there:
{{GAME_SPEC:style,audio,input}}

1. STYLE AND DRAW KIT (module "draw")
Flat fills only: no gradients, shadows, filters or textures. Colors only through palette tokens. System font from style.fontFamily, sizes from style.fontSizes (weights 800 for titles and score, 600 otherwise).
- shape(look, x, y, scale): look = {shape, color, size, w?, h?}; shapes: circle, rect, roundRect, triangle, diamond, hexagon, ring.
- text(str, x, y, sizeKey, colorToken, align); cache HUD strings, rebuild only when the value changes.
- button(label, rect, primary): roundRect radius ui.buttonRadius, fill surface, outline line (player for primary), min height ui.minTouch, min width ui.buttonMinWidth, pressed state fill line.
- bar(rect, ratio, colorToken), panel(rect).
- Pause icon: two bars, top-right, ui.minTouch target.
Feedback helpers driven by style.feedback: hit flash, rising "+N" popup (pickup color), screen shake (only if shakeEnabled), squash, particle burst (pooled squares), state fades. All pooled, capped by limits.particles and limits.popups.
HUD layout: score top-left (hudScore) with a secondary line below (hudSecondary), timer/progress top-center, pause top-right, anchored to the visible screen edges + safe margin.

2. INPUT (module "input")
Gameplay reads actions only, never raw events. Bindings from input.bindings: {action: {keys: [KeyboardEvent.code...], pointer: gesture}}. API: isDown(a), wasPressed(a), wasReleased(a), plus analog vectors for move/aim when a game needs them.
Pointer Events only (covers mouse and touch), pointer capture, multi-pointer by pointerId. Gestures with thresholds from input.gestures: tap, hold, swipeLeft/Right/Up/Down (fires once at threshold), drag, zoneLeft/zoneRight (half of the stage), joystick (floating, radius joystickRadius), pointerAim.
Canvas touch-action: none; prevent default for game keys, scrolling, zoom, context menu and text selection. No hover-only or right-click interactions. Press buffer of input.bufferTime. Release all actions on pause and blur.
Every UI button is clickable/tappable AND reachable by keys: confirm = Enter/Space, pause/back = Escape/P. On Title and Result, any tap or confirm outside a button starts/restarts.
Title shows two control hints, text.controlsKeyboard and text.controlsTouch; highlight the one matching the last input used.

3. AUDIO (module "audio")
Web Audio API only, no files. One AudioContext created/resumed on first user gesture. Master gain = audio.masterVolume if platform.isAudioEnabled() else 0; update via onAudioEnabledChange. No in-game mute button. play(name) builds the sound from the audio.sfx recipe: oscillator (wave, freq to freqEnd slide, duration, volume, quick attack, exponential release); "noise" uses one pre-generated noise buffer. Max audio.maxVoices voices, drop extras, drop the same sound retriggered within 0.03 s. Suspend in PAUSED, resume on leaving it. Play uiTap on buttons, start on PLAY, win/lose on RESULT.

4. SAVE (module "save")
Format: JSON string {"v":1,"best":0,"runs":0,"progress":{}}. Load at BOOT through platform.loadData with tolerant parsing (empty or broken = fresh save, never an error). Save on RESULT and on SDK pause; check isWellFormed when available. best uses exactly the value sent with sendScore.

5. CHECK
Title, Paused and Result screens use the kit and look consistent. Test all screens at 9:16, 1:1 and 21:9, with keyboard only and with touch only.
